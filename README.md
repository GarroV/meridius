# MERIDIUS

Система цифровых чек-листов для сети пиццерий: стандарт заводится в вебе,
попадает на кухню через QR-наклейку и возвращается проверяемой историей.

Ежедневные проверки в пиццерии — открытие смены, состояние оборудования,
чистота зон — обычно живут на бумаге или в голове. Управляющий не может
сказать, что именно проверили вчера в 11 утра, а методист не может поменять
стандарт сразу во всей сети. Продукт закрывает это одной цепочкой: методист
заводит чек-лист в вебе, печатает QR-наклейку для станции, сотрудник на кухне
сканирует её телефоном и заполняет чек-лист, а управляющий видит заполнения
лентой и получает сигнал, когда что-то пошло не так.

## Три поверхности

| Поверхность                   | Кто пользуется        | Что делает                                                                                                                                                |
| ----------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Кабинет `/admin`              | Методист, управляющий | Справочник стран, пиццерий и станций; редактор чек-листов с версиями; библиотека переиспользуемых блоков; печать QR-наклеек; лента заполнений с тревогами |
| Заполнение `/s/<код станции>` | Линейный сотрудник    | Открывается по QR без регистрации и входа: чек-лист, нужный именно этой станции и этому времени суток                                                     |
| Планшет станции `/station`    | Линейный сотрудник    | Постоянно открытая вкладка на планшете у станции: тот же чек-лист без набора адреса и без выбора. Привязывается один раз кодом с экрана `/pair`           |

Сотрудник на кухне не опознаётся: ни входа, ни PIN, ни имени в отметке.
Заполнить может любой, кто отсканировал наклейку или подошёл к планшету, — это
осознанное решение, а не упрощение: 20 секунд между делами не оставляют места на
вход в систему. Планшет станции этого не меняет: привязана ВКЛАДКА к станции, а
не человек к продукту.

## Как посмотреть

Нужны Docker и Node.js. Одной командой:

```bash
cp .env.example .env     # значения по умолчанию годятся для локального запуска
npm ci
npm run up
```

`npm run up` поднимает базу в Docker, накатывает миграции, заводит
демонстрационный контур на английском, собирает и запускает продукт. В конце
печатает адрес кабинета и ссылки станций — те самые, что уходят внутрь
напечатанного QR-кода. Останавливается по Ctrl-C.

Той же командой стенд готовится и там, где сервер держать нельзя — в CI, в
приёмке, перед сквозным смоком:

```bash
npm run up -- --no-start    # довести стенд до готовности и выйти
npm run start               # запустить сервер отдельно, когда нужно
```

Демонстрационные данные идемпотентны: `npm run seed:demo` возвращает контур в
исходное состояние и не плодит дубликатов.

## Справочник сети

Рядом с показательным контуром в базе живёт справочник сети: страны, где сеть
работает, и пиццерии внутри них. Заводится из снимка — файла **вне
репозитория**: репозиторий публичный, а справочник точек сети — внутренние
данные, поэтому пути по умолчанию у команды нет сознательно (D134, тот же
порядок, что у пакета чек-листов).

```bash
npm run import:network -- <путь к network.json>
```

Заводятся только страны и пиццерии, пустыми: станции и чек-листы импорт не
создаёт — что к чему привязано, решает методист. Прогон идемпотентен, повтор
ничего не дублирует, а `Demoland` остаётся показательным контуром: импорт его
не трогает, и `seed:demo` снимает только свои строки, поэтому заведённую сеть
не стирает.

## Устройство

Next.js (App Router) на TypeScript, PostgreSQL через Drizzle, Tailwind поверх
токенов дизайн-системы, next-intl для двух языков интерфейса. Код разложен по
блокам в `src/blocks/<блок>/`; импорт разрешён только в сторону зависимостей, и
это проверяется машинно, а не договорённостью.

| Блок      | Зачем                                                                  |
| --------- | ---------------------------------------------------------------------- |
| `core`    | Каркас, конфиги проверок, единая команда прогона                       |
| `data`    | Схема, миграции, слой доступа к данным                                 |
| `auth`    | Вход в кабинет и защита его маршрутов                                  |
| `catalog` | Страны, пиццерии, станции; привязка чек-листа к станции                |
| `editor`  | Редактор чек-листов: секции, пункты, черновик и публикация версии      |
| `library` | Библиотека блоков: правка в одном месте, вставка в чек-листы           |
| `qr`      | Код станции, перевыпуск, лист A4 для печати                            |
| `fill`    | Публичный экран заполнения по QR                                       |
| `feed`    | Лента заполнений, карточка заполнения, тревоги                         |
| `device`  | Привязка планшета к станции: код, вкладка `/station`, раздел устройств |
| `demo`    | Демонстрационный контур на английском                                  |

## Проверки

```bash
./scripts/check
```

Один список команд на всех: его зовёт приёмка, хук `pre-push` и CI — три
отдельных списка разъезжаются, один не разъезжается. Внутри: формат, типы, линт
с типами, модульные тесты с покрытием, поиск мёртвого кода, границы модулей и
сквозные сценарии в настоящем браузере. Падает, когда инструмента нет: молча
пропущенный гейт неотличим от пройденного.

Миграции пишутся руками — парой файлов `000N_имя.sql` и `000N_имя.down.sql`
плюс запись в журнале миграций. `npm run db:generate` намеренно отказывает и
объясняет почему.

## Лицензия

Файла лицензии в репозитории нет, то есть по умолчанию все права сохранены за
автором: код открыт для чтения, но не для использования. Понадобится иное —
это решение владельца, а не умолчание.
