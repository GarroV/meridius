# Карта соответствия: модуль эталона → блок → задачи

Зачем она нужна. Стройка раздаёт работу по плану блоков, а не по эталону. Модуль
эталона, которому не сопоставлен блок, стройка **не увидит вовсе** — и заметить
это нельзя ничем, кроме этой таблицы: экран просто не будет построен, и никакая
проверка на его отсутствие не сработает.

Карта заведена 13.09.2026, когда проект уже был построен почти целиком. До неё
проверка «нет ли модулей эталона без блока» не делалась ни разу — требование
появилось в системе позже этого проекта (задача T132, issue #43).

## Что в эталоне есть, а отдельного экрана не имеет

- `docs/furca/design/reference/tokens.css` и `components.css` — токены и
  компоненты дизайн-системы. Их потребляет каждый экран; за сам слой отвечает
  `core` (T101, T105, T112).
- `index.html` и `artifact.html` в корне `docs/furca/design/` — оболочка показа
  эталона, а не экран продукта. Блока не требуют.

## Экраны продукта, у которых модуля эталона НЕТ

Обратное направление той же проверки, и оно нашло больше, чем прямое. Эти экраны
строились без эталона — сверять их не с чем:

| Экран | Блок | Чем закрывать |
|---|---|---|
| `/admin` — главная кабинета | `core` | Появилась в T105 и T112 позже эталона; модуля нет |
| `/admin/checklists/new` — заведение чек-листа | `editor` | Строился по `editor.html`, своего модуля нет (именно здесь жил дефект T129) |
| `/admin/checklists/<id>/preview` — предпросмотр | `editor` | Строился по `fill.html`, своего модуля нет |
| `/admin/checklists/<id>/delete` — подтверждение удаления | `editor` | Модуля нет; подтверждение описано только в `states.html` |
| `/admin/qr/screen` — вывод кода на планшет станции | `qr` | Это и есть тот экран, под который нужен второй документ эталона (T108) |
| `/admin/[...unknown]` — чего нет в кабинете | `core` | Модуля нет; ближайшее — «ошибка» в `states.html` |

Это не повод останавливать стройку: продукт построен, экраны работают. Но
«сверено с эталоном» про них сказать нельзя, и T108 закрывает только один из
шести.

## Известное расхождение эталона с продуктом

- **Полосы тревог на ленте в эталоне нет вовсе** — она появилась в продукте
  (T047, T114), и `feed.html` про неё не знает. Расхождение **признано записью,
  а не закрыто перерисовкой**: владелец ответил на Q009 решением D063 —
  «хватит текста», три вида тревоги различаются только формулировкой, третий
  «плохой» цвет тега в дизайн-систему не заводится. Дорисовывать в эталоне
  нечего, кроме самой полосы, а весь груз различения несёт текст. Следующему,
  кто сверяет ленту с `feed.html`: полоса над лентой — **не лишний блок**,
  сносить её нельзя. Различимость трёх формулировок на обоих языках держит
  `src/blocks/feed/alarm-text.test.ts`: общий сторож словаря её не видит —
  полоса зовёт словарь собранным ключом.
- **Второго документа эталона** — планшет на станции и уведомления — нет
  (задача T108, issue #17). Экраны планшета
  строятся по `qr-sheet.html` и `fill.html`, отдельного модуля у них нет.
