# Block: catalog

## Назначение

Справочник: страны, пиццерии, станции и привязка чек-листа к станции. Три колонки, читающиеся как путь.

## API-контракт

```ts
listCountries(); createCountry({ name, locale }); updateCountry(id, ...); deleteCountry(id)
listStores(countryId); createStore({ countryId, name, timezone }); updateStore(id, ...)
deleteStore(id, { confirmed })
listStations(storeId); createStation({ storeId, name }); updateStation(id, ...); deleteStation(id)
reissueStationCode(stationId): Promise<{ code: string; issuedAt: Date }>
assignChecklist(stationId, checklistId); detachChecklist(checklistId); listUnassignedChecklists()
listTimezones(); assertKnownTimezone(name): Promise<string>
```
Код станции — 10 символов из алфавита без похожих знаков, криптографически случайный.

Отличия от исходной записи контракта: у страны нет собственного `id` во входе (его выдаёт база), а к списку добавлены правка и удаление — они требуются задачей T015, но в первой редакции контракта не были выписаны.

## Зависимости

`data`, `auth`

## Definition of Done блока

1. Страна → пиццерия → станция создаются и правятся из интерфейса.
2. Удаление пиццерии со станциями требует подтверждения и не оставляет висячих станций.
3. Станция без назначенного чек-листа помечена явно.
4. Перевыпуск кода: старый код перестаёт открывать чек-лист сразу, новый работает.
5. Экран совпадает с эталоном `docs/furca/design/screens/catalog.html`.

## Решения, принятые внутри блока

| Решение | Почему |
|---|---|
| Алфавит кода станции — 31 знак (`23456789` + латиница без `i`, `l`, `o`), длина 10 | Похожие знаки стоят дороже одного бита энтропии: код переписывают с наклейки и диктуют по телефону. 31^10 ≈ 8·10^14 — перебор через публичный маршрут неосуществим и без ограничения частоты |
| Байты источника случайности отбираются с отклонением, а не берутся по остатку | `байт % 31` даёт первым восьми знакам перевес в 12,5%: перебор сужается, а на глаз код прежний. Закреплено тестом на равномерность, который падает на наивной версии |
| Уникальность кода держит база, а слой повторяет попытку | Выборка «занят ли код» перед вставкой не спасает: между выборкой и вставкой встаёт вторая вставка. Пять попыток, потом честный отказ вместо молчаливой пятисотки |
| Время выпуска кода — `now()` базы, а не время машины | То же правило, что во всём продукте: отметки времени сервера ставит сервер |
| Страна удаляется только пустой, пиццерия — с подтверждением и вместе со станциями | Каскад «страна со всеми пиццериями» одним нажатием необратим и не нужен ни одному сценарию. У пиццерии каскад по станциям нужен (станции без пиццерии не существует), поэтому он есть — но за подтверждением |
| Подтверждение удаления пиццерии — правило слоя, а не разметки | Экран отправляет удаление без подтверждения, слой отказывает кодом `confirmationRequired`, и экран показывает подтверждение. Так правило проверяется тестом и не зависит от памяти того, кто рисовал кнопку |
| Удаление станций и пиццерии — одна транзакция | Отказ на любой станции (на неё ссылаются заполнения) откатывает всё: висячих станций после неудачи не остаётся. Проверено отрицательным прогоном — нетранзакционная версия теряет свободную станцию |
| Отказы блока — код-перечисление, а не текст | Один и тот же набор значений в коде, в адресе экрана и в словаре: забытый перевод виден типами. Текст исключения годится журналу сервера, но не методисту |
| Часовой пояс проверяется по списку зон самого PostgreSQL, а не по `Intl` | Падает именно база, и спрашивать надо у неё: `Intl` движка и `pg_timezone_names` — разные списки. Список кэшируется на процесс: он меняется только с обновлением базы |
| Проверка пояса стоит в слое (`createStore`/`updateStore`), а не в форме | Форма — не единственный путь записи: есть сид демо-контура, миграция данных и будущий импорт. Проверка в форме защищала бы только форму |
| Имя зоны приводится к каноническому написанию | PostgreSQL принимает `asia/almaty` в запросе, но две одинаковые пиццерии не должны выглядеть в справочнике разными |
| Состояние экрана живёт в адресе, а не в памяти браузера | Ссылкой можно поделиться, выбор переживает перезагрузку, а экран остаётся серверным — формы работают и с выключенным JavaScript. Всё, что приходит из адреса, разбирается строго: не-uuid и неизвестные значения отбрасываются до запроса |
| Чек-листы станции показываются в порядке дня (`window_start`), а не по алфавиту | Сортировка по названию потребовала бы выбрать язык прямо в запросе, и порядок в русском и английском интерфейсе разошёлся бы |
| Каркас админки (меню, верхняя полоса) лежит внутри блока `catalog` | Это первый экран админки; куда его вынести, станет видно на втором. Класть его в `core` сейчас значило бы править чужой блок посреди параллельной стройки |
| ~~`DetailCards.tsx` — 460 строк при принятом в проекте пределе 400~~ **Снято задачей T073** (10.09.2026): предел держится, файл разбит | Осознанное отступление. Файл уже разгружен: формы создания сведены к общей, строка чек-листа вынесена, карточки подтверждения переехали в композицию экрана. Оставшееся — три разные формы правки и привязка чек-листов; дробить дальше пришлось бы обёртками на десяток пропов, то есть менять читаемость на число. **Почему снято:** дробить обёртками действительно не понадобилось — граница нашлась не по числу пропов, а по сущности (страна / пиццерия / станция), см. строку ниже |
| Карточки правки разложены по файлу на сущность, а не сведены к одной обобщающей (T073) | У страны, пиццерии и станции разные поля; общего у них ровно оформление — оно и вынесено в `detail-card-kit.ts`. Три похожие карточки лучше одной преждевременно обобщающей: обобщение пришлось бы кормить десятком пропов и флагов, а читать его — вместе со всеми тремя случаями сразу. Классы, нужные одной карточке, остались в её файле: общий модуль — язык оформления, а не свалка констант |
| Адрес раздела QR справочник собирает сам, а не берёт готовый `qrHref` из блока `qr` (T107) | Границы модулей запрещают справочнику импортировать `qr`: зависимость идёт в обратную сторону — это блок `qr` читает справочник, и обратный импорт дал бы цикл. Общий факт взят оттуда, где он доступен обоим: сам адрес раздела лежит в `core/admin-sections`, рядом с боковым меню. Имена параметров (`store`, `station`) остаются договорённостью двух блоков — типами их через границу не связать |
| Совпадение имён параметров с блоком `qr` держит сквозной сценарий, а не модульный тест (T107) | Модульный тест внутри `catalog` не имеет права импортировать `qr` — он упал бы на границах модулей раньше, чем что-то проверил. Разъехаться имена могут только молча, поэтому проверка идёт настоящим переходом в браузере: справочник собирает ссылку, раздел QR читает адрес, и на карточке планшета обязана оказаться ровно выбранная станция (`e2e/catalog-qr.spec.ts`) |
| Кнопка «QR-коды станций» не бывает неактивной ни в одном состоянии экрана (T107) | Пиццерия не выбрана — ссылка ведёт в сам раздел, где экран QR предлагает выбрать. Неактивная кнопка человеку неотличима от сломанной: именно так эти две и прожили месяц после того, как раздел QR был построен |
| Разделы, которых ещё нет (`Чек-листы`, `Библиотека`, `Заполнения`, `QR-коды`), нарисованы, но неактивны | В эталоне они есть, а маршрутов ещё нет: живая ссылка вела бы в 404. Пункт остаётся на своём месте и помечен как ещё не готовый |
| Поле «Страна» в карточке пиццерии — текст (`FIELD_VALUE_CLASS`), а не `<select>`, в том числе не отключённый (T117) | Перенос пиццерии между странами эта версия не делает — реализовывать его не входило в задачу. `<select disabled>` читался как «сломано» или «нет прав» (тот же класс дефекта, что кнопки QR T107, пункты меню кабинета и «Открыть блок» редактора), но и обычный включённый список с одним пунктом был бы нечестным: приглашал бы к выбору, которого на деле нет. Эталон здесь не помог — `docs/furca/design/screens/catalog.html` рисует это же место обычным `<select>` с одним `<option>` без атрибута `disabled`, то есть макет вообще не различает «поле недоступно» и «поле с одним вариантом», а `app.css` эталона не определяет свой вид для отключённого поля (в отличие от `reference/components.css` — но это, по объявлению самого `eslint.config.mjs`, чужой эталон дизайн-системы, не наш). Решение — не элемент формы вовсе, а текст той же высоты и рамки, что у соседних `input`/`select`, чтобы ряд не рассыпался |
| Отказ удаления различается по ИМЕНИ ограничения, а не по коду ошибки (T154) | Код `23503` один на все внешние ключи, и сплошной перевод «ссылаются заполнения» врал: пиццерия не удалялась из-за режима смены, а человек шёл искать историю, которой нет. Имя ограничения — единственное, что отличает правило продукта (история неприкосновенна) от настройки, которую надо снять |
| Режим смены снимается вместе с пиццерией, а `restrict` на `store_shift_modes` остаётся (T154) | Каскад в базе снял бы режим на любом пути удаления, в том числе мимо `deleteStore`; `restrict` оставляет сторожа на месте, а снятие делает слой — видимой строкой в транзакции, а не невидимым правилом схемы |
| Перевыпуск кода станции спрашивает подтверждение, и правило стоит в решении действия, а не в разметке (T260) | Перевыпуск необратим и бьёт не по экрану, а по бумаге: все напечатанные наклейки станции перестают работать в ту же секунду, а узнают об этом сотрудники у стойки. До T260 между промахом мышью и этим исходом не было ни одного шага. Правило в разметке защищало бы только ту кнопку, о которой вспомнили (и не защитило: у блока `qr` своя кнопка перевыпуска, и она по-прежнему без вопроса); правило в `reissueOutcome` закрывает и прямую отправку формы мимо экрана. Тот же порядок, что у удаления станции |
| Подтверждение перевыпуска — модальное окно, а не карточка под деревом, как у удаления (T260) | Перевыпуск запускается кнопкой в СТРОКЕ станции: взгляд человека в этот момент на таблице, а не под ней, и карточка внизу осталась бы незамеченной ровно в том сценарии, ради которого задача заведена. Эталон `states.html` рисует это состояние карточкой, но там карточка — рамка галереи состояний, а не место на экране. Идиома окна взята у единственного другого диалога продукта (`editor/ui/ScheduleChip.tsx`), классы повторены, а не вынесены: общего места для окон нет, а границы модулей запрещают справочнику импортировать редактор. Появится третье окно — выносить в `core` |
| После подтверждения экран уходит на печать наклейки, а не обратно в справочник (T260) | Обещание кнопки — «перевыпустить И открыть печать». Без второго шага методист уходит со старой наклейкой на станции и новым кодом в базе, то есть ровно в то состояние, от которого задача защищает. Адрес печати собирается тем же `qrStationsHref`, что и кнопки «QR» (T107), — вторая копия адреса раздела не заводится |
| Тексты окна приходят пропами, а не берутся словарём внутри клиентского компонента (T260) | Клиентскому `useTranslations` нужен свой `NextIntlClientProvider` с разделом справочника — словарь раздела уехал бы в браузер ради четырёх строк. Та же идиома уже в блоке `qr` (`StationsCard.tsx`: `reissueLabel` пропом). Поймано первым живым прогоном: окно печатало `catalog.confirm.reissueTitle` вместо текста, потому что корневой провайдер отдаёт в браузер только раздел `failure` |
| Снятый с работы чек-лист справочник не предлагает и привязать не даёт | Снос пиццерии отвязывает её чек-листы (`on delete set null`), и архивные оседали в списке свободных: у методиста их нет, а справочник предлагал вернуть в работу снятое. Проверка стоит в записи (`update ... where archived_at is null`), а не до неё: чек-лист снимают с работы и в ту минуту, когда экран уже показал список |

| Задача | Кем | Что сделано |
|---|---|---|
| T016 | сам | Код станции: алфавит без похожих знаков, `randomBytes` с отбором с отклонением. Прямое исключение из правила делегирования — это единственная защита публичной ссылки (D021). **Отрицательные прогоны:** отбор снят (`байт % 31`) — упал тест равномерности (`знак «2» выпал 10955 раз при ожидаемых 10000`); источник заменён на `Math.random` — упали два теста (`expected "random" to not be called at all, but actually been called 200 times` и тот же перекос) |
| T016 (перевыпуск) | сам | `reissueStationCode` в `stations.ts`: новый код и серверное время выпуска. **Отрицательный прогон:** перевыпуск перестал менять код — упали три теста, включая сквозной (`expected { version… } to be null` — старый код продолжал открывать чек-лист) |
| T017 | сам | Привязка и отвязка чек-листа, список свободных, пустой список чек-листов у станции как признак «не назначен». Написано вместе с `stations.ts`, потому что живёт в тех же запросах |
| T015 (страны и пиццерии) | исполнитель | `countries.ts` и `stores.ts` с тестами по готовому контракту: механические запросы, без миграций, политик доступа и денег — случай, когда задача обязана уходить исполнителю. 15 тестов, три отрицательных прогона (подтверждение, транзакционность, запрет по истории). Красный прогон исполнитель сделал задним числом, заглушками `throw new Error("not implemented")` — засчитан, но это уступка: тест обязан писаться раньше кода, а не проверяться на честность после |
| T015 (станции) | сам | Станции остались за мной: в том же файле живёт перевыпуск кода, то есть защита публичной ссылки, — условие «не трогает политики доступа» не выполняется |
| T015 (приёмка исполнителя) | сам | Разбор кода: замечаний по существу нет. Убрал спекулятивный экспорт `storeExists`, который написал сам и нигде не использовал |
| T062 | сам | Проверка часового пояса при создании и правке пиццерии по списку зон PostgreSQL. **Красный прогон настоящий:** четыре теста написаны до правки и упали на ней — `Asia/Almatyy` спокойно доезжал до базы (`promise resolved "'aa4fad30…'" instead of rejecting`). Пятая строка — тот самый урок «одна порча доказывает только себя»: первая версия проверки (текст + видимость + `disabled`-в-карточке) была бы зелёной и на настоящем `<select>` без атрибута `disabled` — то есть пропустила бы ровно тот сценарий, который правилам задачи запрещён явно («перенос пиццерии между странами эта версия не делает»). Проверку тега добавил после этого прогона, не до.

карточкой галереи, а построено окном (решение выше). Английского текста плашки в эталоне
нет вовсе — сверять его не с чем.

Экран снят в браузере (рабочая сборка, 1440×900) и сличён с `docs/furca/design/screens/catalog.html`, открытым рядом.
