# Block: qr

## Назначение

Коды станций, их перевыпуск, лист A4 для печати наклеек и вывод QR на экран планшета. QR принадлежит станции, а не чек-листу: наклейка печатается один раз и живёт годами.

## API-контракт

```ts
stationQrSvg(code: string, origin: string): string      // SVG для экрана и листа печати
stationStickerSvg(code: string, origin: string): string // тот же код файлом: 42 мм вместо «100%»
stationScanUrl(origin: string, code: string): string // ссылка наклейки: <origin>/s/<код>

/admin/qr?store=<uuid>[&station=<uuid>][&confirm=reissue]  // экран печати листа
                                               // confirm=reissue — открыт вопрос
                                               // о перевыпуске кода станции (T266)
/admin/qr/screen?store=<uuid>&station=<uuid>   // полноэкранный QR для планшета
/admin/qr/code?store=<uuid>&station=<uuid>     // { code, issuedAt } — опрос планшетом
/admin/qr/sticker?store=<uuid>&station=<uuid>  // наклейка файлом: SVG, 42 мм, attachment
```
Печать — из браузера: `@media print` и `@page { size: A4; margin: 10mm }`. Серверного PDF нет (D016).

Отличия от исходной записи контракта, все с причинами в разделе решений ниже: у `stationQrSvg`
появился второй аргумент (в наклейку обязан попасть абсолютный адрес); параметры адреса названы
`store` и `station`, и адрес планшета несёт оба (справочник не отдаёт станцию по её
идентификатору); добавлен маршрут опроса `/admin/qr/code` — без него планшет не узнал бы
о перевыпуске кода. Источник ссылки задаётся переменной окружения `PUBLIC_BASE_URL`
(по требованию по фактам целевой площадки), иначе берётся адрес запроса.

## Зависимости

`catalog`, `auth` (экран и перевыпуск закрыты входом — граф блоков в `plan.md` называет `qr`
среди потребителей `requireAdmin()`, и таблица в `.dependency-cruiser.cjs` приведена к нему)

## Definition of Done блока

1. Код читается камерой телефона с распечатанного листа — проверено на настоящей печати, а не на экране.
2. На листе A4 помещаются наклейки всех станций пиццерии, у каждой название станции и пиццерии.
3. При печати не выводятся элементы интерфейса: меню, кнопки, фон.
4. Экран планшета показывает QR крупно и не гаснет.
5. После перевыпуска кода экран планшета показывает новый код без ручного обновления страницы.
6. Экран совпадает с эталоном `docs/furca/design/screens/qr-sheet.html`.

## Сверка с эталоном

Экран снят в браузере (рабочая сборка, 1440x900) и сличён с `docs/furca/design/screens/qr-sheet.html`, открытым рядом в том же браузере. Совпадают: каркас и меню, крошка и заголовок, предупреждение, карточка «Лист для печати» со счётчиком «A4 · 3 станции», сам лист в две колонки с наклейками 34 мм, таблица станций с колонками и кнопкой перевыпуска, карточка планшета с кнопкой «Открыть во весь экран» и подписью под ней.

Расхождения — все осознанные:

## Решения, принятые внутри блока

| Решение | Почему |
|---|---|
| `stationQrSvg(code, origin)` — второй аргумент вместо одного в контракте | В наклейке обязан быть абсолютный адрес: код читает камера телефона снаружи браузера, относительный путь ей открыть неоткуда. Контракт блока записан до того, как этот вопрос возник |
| Кодирует библиотека, рисует блок (`QRCode.create` + свой обход матрицы) | У `qrcode` рисование SVG асинхронное (`toString`), а печатному листу и экрану картинка нужна прямо в рендере. Обход матрицы — двадцать строк, зато функция синхронная, как и обещал контракт, и формат картинки наш: горизонтальные пробеги вместо прямоугольника на каждый модуль |
| Уровень коррекции `Q` (25%), а не привычный `M` | Наклейка печатается один раз и живёт годами в рабочей зоне кухни. Прогоном подтверждено: пятно в 7,4% кода при `Q` читается, при `M` и `L` — уже нет. Плата — код на четыре модуля крупнее, на 42 мм это 1 мм на модуль |
| В разметку картинки не попадает ни код, ни ссылка — только геометрия | Подставить через код станции в SVG нечего в принципе, а не «мы экранируем». Закреплено тестом |
| Публичный адрес продукта — из переменной окружения `PUBLIC_BASE_URL`, а не из кода | Требование диспетчера по фактам площадки: наружу продукт смотрит туннелем (`https://<хост>:10000`), а на машине разработчика это `http://localhost:3100`. Зашитый адрес означал бы, что после переезда все наклейки сети — мусор, а перепечатка ровно то, чего конструкция избегает (D006). **На раскатке:** значения переменных запекаются сборкой (D033), поэтому смена адреса требует пересборки — иначе выглядит как «поменяли адрес, а коды старые» |
| Переменная не задана — адрес берётся из запроса, а заданная мусором роняет экран | Свежий клон и прогон сценариев работают без `.env`, и падать там, где достаточно взять адрес запроса, незачем. А вот подмена мусорного значения умолчанием — это тихая ошибка, которую находят уже наклеенной, поэтому она отказ. Действующий адрес показан прямо на экране печати: лист, снятый с `localhost`, видно до того, как наклейки уедут в пиццерию |
| Адрес планшета несёт и пиццерию, и станцию (`?store=…&station=…`) | В контракте блока стоял только `stationId`, но справочник не умеет отдавать станцию по её идентификатору: без пиццерии каждый опрос планшета перебирал бы весь справочник. Ссылки собирает сам экран, руками их никто не набирает |
| Экран планшета опрашивает свой код раз в 10 секунд и перерисовывается сервером | Требование «после перевыпуска новый код без ручного обновления». Сервер-отправитель (SSE, LISTEN/NOTIFY) держал бы отдельное соединение с базой на каждый планшет ради события, которое случается раз в месяц. Картинку в браузере не рисуем: тогда на бумаге и на экране код собирали бы два разных кодировщика |
| Экран не гаснет через Wake Lock, а его отсутствие не ломает экран | На планшете у станции гаснущая подсветка означает, что сотрудник сначала будит экран, потом сканирует. Браузер без Wake Lock (или запрет политикой) не повод показывать ошибку: QR продолжает висеть |
| Блоку `qr` разрешён импорт `auth` в `.dependency-cruiser.cjs` | Граф блоков в `docs/furca/plan.md` (строка про `auth`) прямо называет `qr` среди потребителей `requireAdmin()`, а таблица в конфиге его пропускала. Экран печати и перевыпуск кода закрыты входом, значит зависимость настоящая |
| Третья копия каркаса админки (меню и верхняя полоса) | Своя копия уже у `catalog` и у `editor`: общий каркас класть некуда, кроме `core`, а править чужой блок посреди стройки нельзя. Копия отличается активным пунктом и своим словарём |
| Экран без пиццерии в адресе показывает выбор пиццерии | В эталоне нарисован лист уже выбранной пиццерии, но попасть на него неоткуда: кнопка «QR» в справочнике неактивна, а чужой блок я не правлю. Выбор — минимальная карточка со списком, без которой раздел недостижим |
| `QR_PATH` читает адрес из `core/admin-sections`, а не хранит свою строку (T116) | Тот же адрес уже жил в `ADMIN_SECTIONS.qr.path` (боковое меню кабинета читает его оттуда). Своя копия строкой могла разойтись с меню молча — ровно так, как уже разъезжались четыре копии списка разделов до T074. Подпути листа (`QR_SCREEN_PATH`, `QR_CODE_PATH`, наклейка) теперь собраны из `QR_PATH`, а не заведены отдельными строками — держит один литерал вместо четырёх |
| `qrcode` тянет в зависимости `yargs@15` ради своего CLI | Известная цена выбора техплана: 15 лишних пакетов, которые продукт не зовёт. В сборку Next они не попадают (импортируется только `create`), поэтому менять библиотеку ради этого не стал — замена остаётся дешёвой, она в одном модуле |
| Наклейка отдаётся файлом SVG, а не PNG, и с размером в миллиметрах | Просьба владельца: «нужна кнопка скачать… формат должен быть векторный, чтоб легко масштаб менялся». Наклейку печатают и 30 мм на полке, и во весь лист на дверь холодильника — растр на втором размере рассыпается, и код перестаёт читаться камерой. Размер задан в миллиметрах, а не долей «100%»: доля означает «сколько дадут в разметке», а в чужой программе, куда файл откроют, давать её некому. Геометрия при этом живёт в `viewBox`, поэтому масштаб свободный. 42 мм — тот же размер, что на печатном листе: наклейки из двух источников обязаны совпадать |

| T266 (issue #131) | сам + исполнитель | Перевыпуск кода станции на экране QR спрашивает подтверждение. **Развилка не переписана, а вынесена:** `core/reissue-confirmation.ts` — одно правило на оба экрана (справочник переведён на него же); окно — `core/ui/ConfirmDialog`, куда переехала копия из `catalog/ui/ReissueDialog.tsx` вместе с её же припиской «появится третье окно — вынести в core»; тексты вопроса не заведены вторыми под `qr`, а берутся из раздела справочника — иначе разъехалась бы фраза, а не код. Состояние вопроса живёт в адресе (`?confirm=reissue`), значит работает без JavaScript и открывается ссылкой. **Главная проверка — не про кнопку:** прямая отправка формы мимо окна в вебе бесплатна, и сквозной сценарий её не ловит, поэтому правило действия закрыто модульной проверкой (`ui/reissue-action.test.ts`), как это уже сделано у справочника. Исполнителю (`optio`) отданы модульные тесты разбора адреса, решения и сборки модели — механика с готовым контрактом; за мной правило, действие, окно и сквозные сценарии. **Отрицательные прогоны:** снят признак подтверждения в действии — краснеет «код станции сменился до подтверждения»; снято требование станции в адресе, инвертирована развилка, подставлена чужая станция в вопрос — краснеет каждая; каждая порча проверена грепом, что применилась. **Смоук живым стендом (3210):** одно нажатие открывает окно с названием станции и предупреждением; Esc и «Отмена» оставляют код прежним (`dmcsdgh358` до и после обоих); подтверждение меняет код (`dmcsdgh358` → `39ctj9yugy`) и оставляет человека на листе печати с перерисованной наклейкой |
| T267 (issue #132), удаление страны | сам | Кнопка «Удалить страну» сносила страну с одного нажатия, хотя станция спрашивает экраном, а пиццерия — слоем. Дано подтверждение: карточка под деревом, как у станции и пиццерии (`confirm=country` в адресе, вид рядом с `store` и `station`). **Вопрос владельцу НЕ заведён** — не потому, что развилки не было, а потому, что её закрыл сам код: комментарий к `CONFIRM_KINDS` в `catalog/ui/view.ts` уже говорил «удаление без подтверждения невозможно по контракту», то есть страна была не решением, а забытым исключением. Поймано сквозным сценарием, не чтением кода. **Отрицательные прогоны:** снята проверка подтверждения в действии — краснеют и модульная проверка («страна удалена до подтверждения»), и сквозная («карточка вопроса не найдена»).
