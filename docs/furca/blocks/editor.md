# Block: editor

## Назначение

Редактор чек-листов — главный экран продукта. Задача блока не «дать возможность создать чек-лист», а сделать так, чтобы чек-лист из двадцати пунктов заводился за минуты.

## API-контракт

```ts
createChecklist({ stationId, title, window }); getDraft(checklistId)
saveDraft(checklistId, sections: Section[])
publish(checklistId): Promise<ChecklistVersion>
duplicateChecklist(checklistId, { toStationId? }): Promise<string>
removeChecklist(checklistId): Promise<'deleted' | 'archived'>   // стереть или снять с работы — по наличию заполнений
previewRemoval(checklistId): Promise<RemovalPreview>            // что произойдёт, для экрана подтверждения
parsePastedList(text: string): Item[]      // строки → пункты, пустые строки и маркеры списка отброшены
```
Формат `sections` — единственный контракт с блоком `fill`, описан в плане.

## Зависимости

`data`, `auth`

## Definition of Done блока

1. Enter в поле пункта создаёт следующий и ставит в него курсор; Alt+↑/↓ переставляют пункт.
2. Вставка 20 строк из буфера превращается в 20 пунктов за одно действие; маркеры списка и нумерация отброшены, пустые строки пропущены.
3. Тип ответа по умолчанию «да/нет»; число принимает границы диапазона; уровень пункта переключается по месту тремя положениями — обычный, важный, критичный (D056).
4. «Сохранить черновик» и «Опубликовать» — разные действия: публикация создаёт версию, черновик остаётся черновиком.
5. Дублирование чек-листа копирует секции и пункты, но не историю заполнений.
6. Предпросмотр открывает тот же экран, что видит сотрудник, с данными черновика.
7. Экран совпадает с эталоном `docs/forge/design/screens/editor.html`.

## Решения, принятые внутри блока

| Решение | Почему |
|---|---|
| Опубликованная версия хранит секцию блока библиотеки как `source: { blockId }` с развёрнутыми пунктами | Снимок — это пункты (D002), а происхождение секции нужно библиотеке: без него `listUsages` (T030) не сможет сказать, сколько опубликованных версий затронет правка блока |
| Публикация освежает ссылки в черновике и только потом зовёт `publishVersion` | Обратный порядок означал бы правку уже созданной версии, а версии неизменяемы. Черновик — единственная мутируемая строка в этой цепочке |
| Пункт без названия пропускается разбором, а не роняет сохранение | Пустая строка внизу списка — обычное состояние редактора: методист нажал Enter и ещё не напечатал текст |
| Пустой чек-лист не публикуется (`nothingToPublish`) | Опубликованная пустая версия — это открытый по QR экран без единого пункта, и понять это можно только на кухне |
| Окно «без ограничения» записывается как `00:00–24:00` | Равные границы запрещены базой (T057), а `24:00` — законное значение `time` в PostgreSQL, делающее условие выбора версии истинным в любую минуту |
| Окно выбирается из трёх готовых вариантов, а не вводится временем | Так в эталоне, и это меньше касаний: у чек-листа станции по сути три окна. Уже записанное нестандартное окно показывается отдельным пунктом списка, чтобы открытие чек-листа не переписало его молча |
| Alt+стрелки переставляют пункт только внутри секции | Пункт, уехавший в соседнюю секцию от одного нажатия, для методиста исчезает: он смотрит на своё место в списке. Требование блока — «переставляют пункт», и оно выполнено без этого риска |
| Вставка в пустой пункт занимает его место | Иначе после вставки списка в только что созданную Enter'ом строку в чек-листе остаётся дырка |
| Тексты пунктов пишутся на языке интерфейса, второй язык не затирается | У методиста нет переключателя языка контента (его нет и в эталоне), а терять уже введённый второй язык нельзя |
| Каркас админки (левое меню) продублирован из блока `catalog`, а не переиспользован | Границы модулей запрещают `editor` зависеть от `catalog` (`.dependency-cruiser.cjs`), а общего места для каркаса в продукте пока нет. Разметка скопирована один в один; правильное место для него — блок `core`, это вынесено наверх диспетчеру |
| Разделы, которых в продукте ещё нет (библиотека, заполнения, QR), показаны неактивными надписями | Ссылка вела бы в 404. Так же поступает `catalog` в своём каркасе |
| У сквозных сценариев своя база `dodo_qr_e2e_<метка копии>` | Рабочую снесла бы подготовка схемы, тестовую посреди прогона пересоздаёт vitest, а экраны редактора читают и пишут настоящие данные |
| Тексты редактора уходят в браузер провайдером `next-intl` | Клиентская часть большая и с числительными («4 пункта», «используется ещё в 6 чек-листах»); пробросить готовые строки нельзя — количество меняется прямо на экране |
| Состояние фильтра списка живёт в адресе, а не в памяти компонента | Тот же приём, что у ленты (`feed/view.ts`): ссылкой на «Кухню Алматы» делятся в чате, и она обязана открыться тем же списком. Заодно экран остаётся серверным и работает без JavaScript кнопкой из `<noscript>` |
| Справочник фильтра выводится из `listStations()`, а не из трёх новых запросов | Запросов не прибавилось, а в списках оказываются только страны и пиццерии, где есть хотя бы одна станция, — то есть только те, где чек-лист вообще может жить. У ленты справочник свой (три запроса), потому что она фильтрует заполнения, а не привязку к станции |
| Выбор станции достраивает пиццерию и страну, а выбор пиццерии — страну | Выбрав «Кухню Алматы», методист выбрал и Алматы: списки обязаны это показать, иначе экран одной станции подписан «Все страны». Побочно чинит вёрстку: без выбранной пиццерии станции названы путём («Алматы, Абая 44 · Кухня»), и выбранное значение не влезало в поле, обрезаясь посреди слова |
| Пустой результат — отдельное состояние, а не «чек-листов пока нет» | Второе звало бы завести новый чек-лист там, где выбрана не та станция, — и в сети появился бы дубль уже существующего. На эталоне этого состояния нет вовсе, поэтому собрано по `.empty` из дизайн-системы |
| Пункт «Все» есть и в списке «Страна», хотя на эталоне его там нет | Без него состояние «фильтр не выбран» невыразимо, а именно оно открывается по умолчанию. Отступление от эталона намеренное, сверка его подтвердила |
| `isUuid` вынесен в файл без импортов | Списки фильтра клиентские, и через `validation.ts` в браузерный бандл затягивался драйвер базы — сборка падала. Поймал только настоящий `next build`: ни типы, ни тесты этого не видят |
| «Удалить» ведёт на отдельный экран подтверждения, а не удаляет сразу | Последствие зависит от истории и его надо назвать заранее: чек-лист без заполнений стирается целиком, а чек-лист, по которому уже заполняли, только уходит из работы (`archived_at`, миграция 0005) — заполнения хранят снимок пунктов, которые видел сотрудник (принцип 3, D002). «Удалить» и «убрать из работы» слишком разные вещи, чтобы выясняться после нажатия. Заодно экран работает без JavaScript, как остальные формы, — всплывающее «вы уверены?» без JS не работает вовсе |
