# Block: device

## Назначение

Планшет пиццерии, закреплённый на станции, открывается сразу в чек-лист своей станции —
без набора адреса, без выбора, без входа. Сотруднику нельзя личный телефон на смене,
значит наклейку он не сканирует; а закрепить вкладку на `/s/<код>` нельзя, потому что код
перевыпускается (D006) и закреплённая вкладка после этого ведёт в отказ.

Решение: управляющий выпускает из кабинета четырёхзначный пин, планшет один раз вводит
его и получает долгоживущую подписанную куку, привязанную к **станции**. Дальше вкладка
живёт на постоянном адресе `/station`, который ничего в себе не несёт.

**Дизайн целиком — `docs/furca/specs/2026-09-22-tablet-pairing-design.md` (D132, D133).**
Читать его до первой строки кода: здесь только контракт и границы, там — механика,
краевые случаи и обоснования.

## API-контракт

| адрес | кто | что |
|---|---|---|
| `/pair` | публичный | страница привязки: поле на четыре цифры, ограничитель попыток |
| `/station` | публичный | привязанная вкладка; в адресе нет ничего |
| `/admin/devices` | кабинет | все станции сети деревом страна → пиццерия → станция с отметкой «планшет привязан / без планшета», пошаговая инструкция привязки с настоящим адресом `/pair` (D163) |
| `/admin/devices?station=<id>` | кабинет | выдвижная панель станции: планшеты с датами, отвязка с подтверждением (`&confirm=<deviceId>`, отказ — `&failed=1`), выпуск кода рядом с инструкцией |
| действие «Привязать планшет» | кабинет | выпуск пина: панель раздела устройств, карточка станции, экран чек-листа; отказ называет причину (#162) |

Наружу блок отдаёт: выпуск пина (`PairTabletCard` — для карточки станции и экрана
чек-листа), чтение живой привязки по куке (для `/station`), станции с планшетами
(`station-tablets.ts`) и отвязку (`UnlinkButton` — для `/admin/devices` и карточки станции).
Полный адрес страницы привязки собирает `src/app/admin/devices/page.tsx` правилом наклейки
(`qr/ui/origin.ts`): блоку `device` ссылаться на `qr` нельзя. Код станции через контракт
**не ходит**: привязка знает `station_id`, код спрашивается у базы при каждой отрисовке и
уходит в существующий `loadFillTarget(code, at)`.

## Зависимости

Права блока — `["fill", "data", "auth", "core"]` в `.dependency-cruiser.cjs`.

**Жёсткий запрет:** `src/app/pair/` и `src/app/station/` не имеют права зависеть от
`blocks/auth` — тот же запрет, что уже стоит на `/s/` (T187). Публичная поверхность не
знает о входе в кабинет, иначе отказ кабинета однажды уведёт человека с кухни на пароль,
которого у него нет.

Адреса публичных маршрутов заводятся в `core/public-routes.ts` рядом с
`PUBLIC_FILL_PREFIX`; политика заголовков берёт их оттуда — второй копии строки адреса в
продукте не будет (T120).

Подпись — общая: HMAC выносится из `auth/session.ts` в `core/signed-token.ts`, оба блока
зовут оттуда. Секрет свой: `DEVICE_SESSION_SECRET` рядом с `SESSION_SECRET`.

## Definition of Done блока

|---|---|

| Пин съедается одним запросом `UPDATE … WHERE used_at IS NULL RETURNING`, одноразовость и срок проверены тестами ДО кода | 3 |

| Кука подписана общим `core/signed-token.ts`; второй реализации подписи в продукте нет | 3 |
| Отвязка мгновенная: на каждый запрос проверяется живая строка устройства | 3 |
| Перевыпуск кода станции привязку не ломает — проверено сквозным сценарием, а не рассуждением | 3 |
| Отказы на `/pair` неразличимы между собой (истёк / неверен / съеден) | 3 |
| Сброс недозаполненного на границе окна: проверено, что ЧЕРНОВИК ПУСТ, а не только что страница обновилась | 3 |
| Раздел `/admin/devices` и страница `/pair` заведены в ОБЕИХ локалях | 3 |
| Сквозной сценарий целиком зелёный (см. ниже) | 3 |
| Каждая новая проверка доступа покраснела на умышленно сломанной копии, и подтверждено, что подмена применилась | 3 |
| AITriage прогнан: это код доступа | 3 |
| `docs/furca/design/map.md` и инвентари маршрутов обновлены тем же заходом | 3 |

**Сквозной сценарий, один и честный:** выпустил пин в кабинете → ввёл на планшете →
вкладка показывает чек-лист станции → заполнил и отправил → отметка видна в ленте →
перевыпустил код станции, вкладка продолжает работать → отвязал из кабинета, вкладка
просит новый код.

## Сверка с эталоном

**Эталона у этого блока нет** — `docs/furca/design/map.md` модуля для экранов планшета не
содержит. Это признанное отступление, а не пропуск: страница привязки строится языком
отбивок `states.html`, раздел устройств — языком `catalog.html`. Отступление записывается
решением (T300), а не остаётся молчаливым.

| Расхождение | Причина |
|---|---|
| Страница привязки `/pair` нарисована языком отбивок `states.html` | Эталона экрана нет вовсе. Взят тот же полноэкранный столбец по центру, что сотрудник уже видит на всех остальных состояниях, — чтобы планшет не выглядел другим продуктом |
| Раздел `/admin/devices` — дерево станций и выдвижная панель справа по механике Swarm Brain (D162, D164) | Эталона экрана нет. Панель — компонент ядра `core/ui/Drawer.tsx` (`.drawer*`), строки — обычный текст с фоном `--surface-2` при наведении. Схемы шагов инструкции — инлайн-SVG на токенах ядра (`ui/PairIllustrations.tsx`), а не картинки: живут в обеих темах |
| Часы, чип звука и отсчёт до открытия добавлены поверх экрана заполнения | Эталон экрана заполнения планшетной вкладки не описывает. Добавки идут в токенах того же экрана и на телефоне не появляются |
| Действие «Привязать планшет» — карточка на экране чек-листа | Эталон экрана чек-листа действия не содержит. Карточка повторяет язык остальных карточек редактора |

## Что в этот блок НЕ входит

- Опознание человека: ни входа, ни PIN у сотрудника, ни имени в отметке (D001). Привязана
  вкладка, а не человек.
- Плитка станций на планшете и код пиццерии в адресе — отклонено D132.
- Проверка, где физически стоит планшет: гео продукт не спрашивает (D003).
- Офлайн (D005), уведомления наружу (D073), правка наклеек и печати.

## Устройство блока

| Файл | Что внутри |
|---|---|
| `pin.ts` | Форма пина без базы: длина, срок, проверка четырёх цифр. Отдельно от `pairing.ts` намеренно — форму знает и клиентская форма ввода, а `pairing.ts` тянет за собой драйвер базы |
| `pairing.ts` | Выпуск пина (чистка прежнего и истёкших + вставка ОДНИМ запросом, повтор на занятом коде) и съедание одним `UPDATE … WHERE used_at IS NULL RETURNING` |
| `devices.ts` | Привязка со снятием прежней в одной транзакции, чтение живой строки вместе со свежим кодом станции, отвязка, «был на связи» |
| `station-tablets.ts` | Все станции сети с их планшетами (левое соединение: станция без планшета не теряется) и одна станция для панели; число чек-листов станции |
| `issue-failure.ts`, `pg-error.ts`, `pin-errors.ts` | Разбор отказа выпуска пина на «временно / станции нет / поломка» (#162); код ошибки PostgreSQL; свой класс «свободный код не нашёлся» |
| `session.ts` | Кука планшета: имя, срок в год, упаковка и чтение подписанного опознавателя |
| `config.ts` | Секрет планшета. Отсутствует, опубликованный из `.env.example`, короче 32 знаков или равный секрету кабинета — отказ, а не тихая работа |
| `current.ts` | Кто пришёл: кука → живая строка в базе (через `cache()`, один запрос на отрисовку), отметка «был на связи», запись куки |
| `pair.ts` | Что происходит на вводе: частота → форма кода → съедание пина → привязка → кука. Порядок такой, чтобы перебор не гонял базу |
| `rate-limit.ts` | Пределы попыток: 10 на клиента и 60 на всех за пять минут |
| `windows.ts` | Часы вкладки: сколько до смены состояния, опознаватель текущего окна, сколько до открытия |
| `params.ts` | Имя заголовка «это вкладка планшета» — лист без зависимостей, потому что его читает `proxy.ts` |
| `ui/PairScreen.tsx`, `ui/PairForm.tsx`, `ui/pair-action.ts` | Страница привязки; действие возвращает уже переведённый отказ (склонение минут считается на сервере) |
| `ui/TabletScreen.tsx`, `ui/TabletExtras.tsx`, `ui/TabletIdle.tsx` | Привязанная вкладка: отбивка «планшет отвязан», часы, удержание экрана, чип звука, отсчёт до открытия |
| `ui/DevicesScreen.tsx`, `ui/StationDrawer.tsx` | Раздел устройств: дерево станций и панель станции справа |
| `ui/PairGuide.tsx`, `ui/PairIllustrations.tsx` | Инструкция по шагам со схемами экрана — одна на экран раздела и панель (`compact`) |
| `ui/UnlinkButton.tsx`, `ui/unlink-action.ts` | Отвязка с вопросом в адресе; адрес экрана может нести свои параметры (`?station=`) |
| `ui/PairTabletCard.tsx`, `ui/PairTabletButton.tsx`, `ui/PairTabletIntl.tsx`, `ui/issue-pin-action.ts` | Выпуск пина: кнопка с отсчётом и отказом по причине; словарь `device.issue` передаётся провайдером только кнопке |

## Состояние

28.09.2026, доработка раздела «Устройства» по D163 (ветка `feat/swarm-devices`, #182). Раздел
показывает все станции сети, а не только привязанные планшеты; станция без планшета помечена;
работа со станцией — в выдвижной панели справа: планшеты с датами «привязан» и «был на связи»,
отвязка с подтверждением, которое называет последствие, выпуск кода с отсчётом рядом с
инструкцией. Инструкция по четырём шагам со схемами экрана и настоящим адресом `/pair` стоит и
на экране раздела. Отказ выпуска кода различает причину (#162) и пишется в журнал сервера.
Esc в окне подтверждения поверх панели закрывает только окно (`core/ui/ConfirmDialog.tsx`
гасит событие).

Тесты до кода — на ядро данных и отказов: `station-tablets.test.ts` (станция без планшета не
теряется, два планшета сворачиваются в одну станцию, соседняя станция не получает чужой планшет,
чек-листы считаются числом, отвязанный уходит, мусор из адреса — `null`) и
`issue-failure.test.ts`. Отрицательные прогоны: внутреннее соединение вместо левого роняет 4
теста, «всё временно» — 2; снятое гашение Esc роняет сквозной сценарий раздела.

Сквозные сценарии (`e2e/device.spec.ts`): раздел → станция без планшета → код в панели → ввод
на планшете → станция с планшетом → Esc закрывает только вопрос → отвязка → планшет просит код;
прежний путь с экрана чек-листа отвязывает через панель. Доступность панели с выпущенным кодом —
`e2e/a11y.spec.ts`.

Не сделано: область видимости тенанта (D145) в разделе не применяется — её нет ни на одном экране
кабинета; перенос планшета отдельной кнопкой не заведён намеренно (это та же привязка).
