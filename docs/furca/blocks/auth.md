# Block: auth

## Назначение

Вход в кабинет управляющего и граница того, что каждому вошедшему видно. Учётки двух видов (D145): **УК** (логин `admin`, пароль из окружения площадки) видит всю сеть; **партнёр** (строка в `accounts`) видит только страны своего тенанта. Граница действует на весь кабинет: чужая запись отвечает тем же, что несуществующая, — 404.

## API-контракт

```ts
signIn(login: string, password: string): Promise<SignInResult>  // "ok" | "rejected" | "throttled"
signOut(): Promise<void>
requireAdmin(): Promise<Viewer>   // нет сессии или учётка снята → redirect на /admin/login
requireHq(): Promise<Viewer>      // партнёр → notFound()

interface Viewer { accountId: string | null; login: string; tenantId: string;
                   tenantKind: "hq" | "partner"; tenantName: string; countryIds: string[] }
type Scope = { kind: "all" } | { kind: "countries"; countryIds: ReadonlySet<string> }

scopeOf(viewer): Scope                   // чем фильтровать выборки
countryCondition(scope, column)          // условие drizzle: undefined для УК, false для пустого списка
checklistVisibleSql(viewer, tenantCol, countryCol)  // то же для чек-листов на сыром SQL
canSee(viewer, "station" | "store" | "submission" | "device", id): Promise<boolean>
requireVisible / requireCountry / requireStations / requireChecklistVisible
  / requireChecklistEditable / requireHqViewer     // отказ — notFound()
WHOLE_NETWORK: Scope                     // явная «вся сеть» для сидов, скриптов и тестов
provisionPartner(input): Promise<ProvisionResult>  // заведение партнёра (экран «Партнёры»)
listPartnerAccounts / changePartnerPassword / resetPartnerPassword
  / disablePartnerAccount                // учётки партнёров; отказ — код, не исключение
```

## Правила области видимости

- Страна, пиццерия, станция, заполнение, планшет видны, если их страна в списке тенанта. УК видит всё без запроса к базе.
- Чек-лист: шаблоны видны всем; свой чек-лист виден всегда (и без станции); чужой — только если висит на станции в моей стране. Править шаблоны — только УК; остальное правится там, где видно.
- Только УК: страны справочника, библиотека блоков, новый шаблон. Партнёру кнопок нет, а действие отвечает 404. Библиотеку партнёр видит списком без ссылок и без редактора; адрес редактора `?block=` ему — 404 (T338, файлы `library`).
- Список станций из формы (копирование, наклейки) отклоняется целиком, если в нём есть хоть одна чужая или несуществующая.
- Тенант и страны читаются из базы на каждый запрос (React `cache`): снятая учётка и отобранная страна действуют сразу.

## Как устроена охрана

- **Перед рендером** — `src/proxy.ts` сторожит `/admin/:path*`, иначе запрос клиентской навигации увозил разметку вместе с редиректом.
- **Экраны** — `src/app/admin/layout.tsx` зовёт `requireAdmin()`; форма входа лежит вне этого каталога (`src/app/(public)/admin/login`), неизвестные адреса ловит `[...unknown]`.
- **Действия и `route.ts`** выполняются мимо разметки и зовут `requireAdmin()` сами; что ни одно не забыто — `e2e/admin-guard.spec.ts`, перебором файлов маршрутов.
- **Данные** — каждая выборка кабинета принимает `Scope` или `Viewer`; что ни один маршрут не отдаёт чужую страну — `e2e/tenant-scope.spec.ts`, тоже перебором маршрутов: новый маршрут без проверки роняет сценарий своим адресом.
- **Кука** — `{v:2, sub, iat, exp}`, `sub` — `"root"` или uuid учётки. Кука прежнего вида (v1) не принимается; смена `SESSION_SECRET` разлогинивает всех.
- **Неизвестный логин** проверяется против подставного хэша: работа сервера та же, что на неверном пароле, и перебор не узнаёт, какие логины есть.

## Учётки

- **УК** — логин `admin`, хэш пароля в `ADMIN_PASSWORD_HASH` (`node scripts/hash-admin-password.mjs`, пароль со стандартного ввода). В базе логин `admin` запрещён ограничением.

  Пароль короче 12 знаков скрипт по умолчанию считать отказывается: учётка УК открывает всю сеть,
  и подбор упирается только в длину. Отступление возможно, но осознанное — флагом `--allow-short`,
  и тогда скрипт печатает предупреждение. Молчаливого пути к короткому паролю нет: без флага — отказ,
  с флагом — предупреждение (D047: короткая учётка на время показа, значение — только в `.env` площадки).
- **Партнёр** — заводит, меняет и сбрасывает пароль, снимает УК на экране «Партнёры» (`/admin/partners`, D169, T337); партнёру адрес и действия — 404. Пароль не короче 12 знаков; страны выбираются из справочника; повтор с тем же названием партнёра добавляет учётку и страны, ничего не снимая; занятый логин — отказ. Сброс выдаёт случайный пароль (16 знаков, `randomInt`) один раз. Снятие (`accounts.disabled_at`) необратимо с экрана и гасит открытые сессии на следующем запросе; смена пароля открытые сессии **не** гасит — в схеме нет отметки смены пароля (см. «Открыто»). Команда `partner:create` снята (#192).

## Переменные окружения

Имена и безопасные значения — в `.env.example`, рабочие — только в `.env`. `ADMIN_PASSWORD_HASH` (формат `scrypt.N.r.p.соль.ключ`) и `SESSION_SECRET` (не короче 32 знаков). Без любой вход никого не пускает; значения в ошибки не попадают. Значения из `.env.example` на `NODE_ENV=production` отказывают отдельной ошибкой.

**Знак `$` в значениях запрещён:** загрузчик `.env` Next молча подставляет `$переменная`, поэтому разделитель в хэше — точка. Проверка — `env-file.test.ts` на настоящем загрузчике.

## Схема

Миграция `0016_tenants_and_accounts` (с `.down.sql`): `tenants` (ровно один `hq` — частичный уникальный индекс), `tenant_countries`, `accounts` (логин уникален, форма `^[a-z0-9._-]{3,64}$`, не `admin`, хэш `scrypt.…`), `checklists.tenant_id` — владелец чек-листа, существующие переписаны на УК.

## Definition of Done блока

1. Любой `/admin/*` без сессии отдаёт форму входа, а не данные — `e2e/admin-guard.spec.ts`, обычным запросом и клиентской навигацией. **Закрыто.**
2. Неверный пароль и неизвестный логин не отличимы по работе сервера — scrypt считается всегда, сравнение `timingSafeEqual`. **Закрыто** (`password.test.ts`, `actions.test.ts`).
3. Пароль и секрет не попадают в разметку, логи и ошибки. **Закрыто.**
4. `/s/*` работает без сессии и блок не импортирует. **Закрыто.**
5. `.env.example` поднимает проект, пример на проде отказывает. **Закрыто.**
6. Перебор ограничен: 5 попыток с клиента за 15 минут, общий потолок 50; место в счёте занимается до проверки пароля. **Закрыто.**
7. Одновременные верные входы с одного клиента не упираются в предел (#170, T313): попытки одного клиента идут через счёт и пароль по очереди (`inClientTurn`, память процесса, глубина не больше `MAX_TURN_QUEUE` = 10 — сверх неё попытка идёт сразу, чтобы залп не держил честный вход), удачный вход снимает счёт до следующей. Граница — место в базе, не очередь: без очереди (перезапуск, вторая копия) залп неверных доходит до scrypt не больше пяти раз. **Закрыто:** `actions.test.ts` (шесть одновременных верных — все `ok`; залп неверных с чистого счёта — ровно пять проверок), `actions-without-turn.test.ts` (очередь выключена — не больше пяти scrypt). Негатив: снятая очередь роняет первый, порядок «сначала пароль, потом счёт» — второй, снятый предел глубины — `rate-limit.test.ts`. `e2e/stations.spec.ts` идёт параллельно.
8. Партнёр не получает чужую страну ни с одного маршрута кабинета (D145). **Закрыто:** `e2e/tenant-scope.spec.ts` обходит все маршруты из `adminRoutes()` — тело каждого ответа без чужих имён, кода станции и id, своё на тех же экранах видно, чужая запись по адресу — 404. Негатив: снятый фильтр станций и выпавший из списка маршрут роняют сценарий.
9. УК ведёт учётки партнёров с экрана, без команды и правки базы (T337). **Закрыто:** `partners.test.ts` (ядро: смена пароля — только своей и только действующей учётке, сброс входит новым паролем, снятие не сдвигает срок, отказ на несуществующей), `e2e/partners.spec.ts` (УК заводит → партнёр видит только свою страну, «Партнёры» ему 404 → сброс: старый не входит, новый входит → снятие: вход отказан, открытая сессия уведена на вход). Негатив: снятая `requireHq` и снятие не той учётки роняют сценарий.

## Развилки продукта

Шесть развилок сдачи T314 закрыты умолчаниями D169: экран УК, логин и пароль, смена/сброс/снятие на экране, черновики шаблонов партнёру видны, справочник — пиццерии и станции своих стран, страна может принадлежать двум партнёрам.

## Открыто

- **Смена и сброс пароля не выставляют уже вошедшего** до выхода: нужна отметка смены пароля в `accounts` (миграция — блок `data`). Экран говорит об этом УК прямо и советует снять учётку.
- **Пункта «Партнёры» в меню нет:** меню и разделы — файлы `core` (`admin-sections.ts`, `AdminNav.tsx`), и меню не знает вошедшего (`core` не импортирует `auth`). Экран открывается по адресу.
- Вернуть снятую учётку с экрана нельзя (не в T337).

## Вынесено наверх

- Заголовков `Content-Security-Policy` и `X-Frame-Options` нет — файл блока `core` (T065).
- **D145 правит чужие блоки:** область видимости навешена точечно в `catalog`, `editor`, `library`, `feed`, `qr`, `stations`, `device`, `data`, `demo` и в `src/app/admin/**` — это их файлы, правки нужно показать их владельцам.

## Расхождения с экранным эталоном

1. **Поле «Логин» над паролем** — в `login.html` его нет (запись в `docs/furca/design/map.md`). Отказ — «Неверный логин или пароль»; автофокус перешёл на логин.
2. Шрифт Golos Text в приложении не подключён, базовый размер текста 16 px вместо 13, парные межстрочные токены — всё это файлы блока `core`, общее для всех экранов.
